## 17. ต้นตอร่วมของข้อ 16 + false negative ของข้อ 12 — **embedding dilution** (วินิจฉัยแล้ว 2026-08-02)

เบาะแสจากข้อ 12 ("คำถามแมตช์บทเรียนของตัวเองเป๊ะแต่ได้ 0.49") ไล่จนเจอต้นตอ
**ไม่ใช่ปัญหาของ threshold และไม่ใช่บั๊ก Thai embedding** — โมเดลปกติ (`cos(t,t)`=1.0)

**ชั้นที่ 1 — embedding คือค่าเฉลี่ยของทั้งข้อความ** (คำถาม `"หาข้อมูลการสร้างหน้า ui แชทบอท"`):

| ข้อความที่เอาไป embed | คะแนน |
|---|---:|
| หัวข้อบทเรียนอย่างเดียว | **0.913** |
| + เนื้อ 40 ตัวอักษร | 0.658 |
| + เนื้อ 80 ตัวอักษร | 0.524 |
| doc เต็ม (ที่ระบบใช้จริง) | **0.490** |

อิ่มตัวที่ ~160 ตัวอักษร · เราเก็บ "คำถาม+คำตอบ" เป็นก้อนเดียวแล้วค้นด้วยคำถาม
→ คำตอบที่ยาวกว่ากลบสัญญาณของคำถาม

**ชั้นที่ 2 — ตัวระบุ (รุ่น/รหัส) เป็นสัญญาณรบกวน** (คำถาม `"เราเตอร์ที่บ้านยี่ห้ออะไร"`):

| ข้อความ | คะแนน |
|---|---:|
| `"เราเตอร์ที่บ้านคือยี่ห้อเอซุส"` | **0.789** |
| `"เราเตอร์ที่บ้านคือ"` | 0.606 |
| `"เราเตอร์ที่บ้านคือ ASUS RT-BE92U"` (ของจริงใน user_facts) | **0.447** |
| `"ASUS RT-BE92U"` ล้วนๆ | 0.287 |

สองประโยคที่ต่างกันแค่ชื่อรุ่นได้คะแนนกันเอง **0.496** = โมเดลแทบไม่เข้ารหัสตัวระบุ
**ประชด: ตัวระบุรุ่นคือสิ่งเดียวที่เราอยากจำ แต่เป็นส่วนที่ embedding เก็บได้แย่ที่สุด**
→ อธิบายข้อ 16 ครบ (ทำให้ fact สะอาดขึ้น = recall แย่ลง) และอธิบาย false negative ของข้อ 12

### ทางแก้ที่ทดสอบแล้วกับ ground truth 50 คู่

| กลยุทธ์ | ที่เกณฑ์ 0.60 | หมายเหตุ |
|---|---|---|
| doc เต็ม (ปัจจุบัน) | P=0.94 R=0.89 | |
| กุญแจอย่างเดียว | P=0.75 R=0.83 | ❌ **แย่ลง** |
| **max(กุญแจ, doc เต็ม)** | **P=0.86 R=1.00** | ✅ ได้ false negative คืนครบ |

- **"index แค่กุญแจ" ตกทันที** — 3 คู่แย่ลง (−0.11 ถึง −0.39) เป็นเคสที่คำถามใหม่ไม่ตรงกับ
  คำถามเดิมแต่ตรงกับ**เนื้อคำตอบ** · ค่าเฉลี่ยดีขึ้น +0.183 แต่จำนวนที่ผ่านเกณฑ์**ลดลง**
  (16/18 → 15/18) — **ค่าเฉลี่ยหลอก ต้องนับรายตัว**
- ⚠️ **max ได้ F1=1.00 ที่ 0.625 แต่เชื่อไม่ได้** — ช่องว่างระหว่างกลุ่มกว้างแค่ **0.013**
  (0.634 vs 0.621) = overfit บน 50 คู่ · เชื่อได้แค่ **แนวโน้ม** (recall 1.00 โดย precision ไม่ตก)

### ยังไม่ลงมือ — ต้องตัดสินใจก่อน
เป็นการเปลี่ยนวิธี index (เก็บ 2 vector ต่อ 1 memory) กระทบทั้ง `remember()`/`teach()`/
`save_lesson()` + ต้อง re-index ของเก่า · ทางเลือกเสริม: ตัวระบุ (รุ่น/IP/เลขที่) อาจต้องใช้
keyword/substring match คู่ไปด้วย เพราะ semantic search จับไม่ได้โดยธรรมชาติ

📖 บทเรียนเต็ม (ใช้ซ้ำข้ามโปรเจกต์ได้): vault `wiki/concepts/embedding-dilution.md`

## ~~7.~~ ✅ auth / rate limit / security — **ตรวจแล้ว 2026-08-03** (ครั้งก่อน 2026-06-01)

### 🔴 A. `/api/auth/login` ไม่เคยเข้าเงื่อนไข brute-force lockout เลย

`rate_limit_middleware` นับ auth failure เฉพาะ request ที่มี header `x-auth-token`
แต่ login ส่งรหัสใน **body** → **endpoint เดียวที่ lockout มีไว้ป้องกัน คือ endpoint
เดียวที่ไม่เคยถูกนับ** เดารหัสได้ไม่จำกัด ติดแค่ RPM (120/นาที = 172,800 ครั้ง/วัน)
และ token ที่ได้จาก login **คือ `UI_PASSWORD` ตัวเดียวกัน** = เดาได้ก็ได้ทุกอย่าง

หลักฐาน (ก่อนแก้ · `AUTH_FAIL_MAX=3`): ยิงรหัสผิด 8 ครั้งติด → `401` ทั้ง 8 ครั้ง
ขณะที่เส้น header ล็อกตั้งแต่ครั้งที่ 4 (`429`)

- **ต้นเหตุ:** เงื่อนไข `had_token` ถูกใส่ไว้ 2026-06-02 เพื่อกัน false lockout ตอนหน้าเว็บ
  โหลดครั้งแรก (ยิง API ไม่มี token) — **overcorrection** ที่กวาด login ติดไปด้วย
- **แก้:** นับเป็น credential attempt เมื่อ *มี header token* **หรือ** *path เป็น `/api/auth/login`*
  (`core/auth.py:LOGIN_PATH`) · เทสคุมทั้งสองด้าน: login ผิดต้องล็อก + request เปล่าที่
  401 บน path อื่นต้องยังไม่นับ (กัน regression 2026-06-02 กลับมา)

### 🔴 B. WebSocket `/ws/voice/{slug}` ไม่มี auth เลย — หลุด public ทั้งเส้น

`app.middleware("http")` = `BaseHTTPMiddleware` ซึ่ง**ลัดผ่านทุก scope ที่ไม่ใช่ `http`**
→ auth / rate limit / request-id **ไม่เคยแตะ WebSocket** แม้แต่ครั้งเดียว
เส้นนี้เปิด session Gemini Live จริง (เผา quota ของ `GEMINI_API_KEY`) และ **เขียนลง
chat history** ได้ · แอปเปิด public ผ่าน Cloudflare Tunnel → ใครมี URL ก็ต่อได้

หลักฐาน (ก่อนแก้ · `UI_PASSWORD` ตั้งไว้): `GET /api/sessions` → `401`
แต่ `websocket_connect("/ws/voice/kwan")` **ต่อติด** และได้ frame แรกกลับมา

- ⚠️ `/ws` อยู่ใน `_OPEN_PREFIXES` อยู่แล้ว → **หน้าตาเหมือนตั้งใจเปิด** ทั้งที่ของจริงคือ
  middleware ไปไม่ถึงตั้งแต่แรก บรรทัดนั้นจึงไม่มีผลอะไรเลย — comment/allowlist
  ไม่ใช่หลักฐานว่ามีใครตัดสินใจ
- **แก้:** `core.auth.websocket_authorized()` — กติกาเดียวกับ `auth_middleware`
  (password ปิด → ผ่าน · LAN peer → ผ่าน · ไม่งั้นต้องมี token) เรียกใน handler
  **ก่อน `accept()`** ปฏิเสธด้วย close code `1008`
- **ฝั่ง client:** browser ตั้ง header บน WebSocket ไม่ได้ → token ไปทาง query param
  `?token=` (`~/appscript.ui/utils/voicelive.ts:voiceWsUrl`, 4 vitest) อ่านจาก
  `localStorage["hw_auth_token"]` · **แก้ backend อย่างเดียว = voice ของคนนอกบ้านพัง**
  ต้อง build + `sync_static.sh` คู่กันเสมอ

เป็น **สองต้นเหตุที่คูณกัน** ต้องแก้ทั้งคู่ แก้อันเดียวไม่พอ:

   หยุดกลางคันไม่ได้** — ไม่ว่าจะเอาไปรันที่ไหนก็กินเธรดนั้นตลอดกาล
2. **บล็อก event loop** — handler เป็น `async def` (เพราะต้อง `await request.json()`)
   แล้วเรียก `search_files` แบบ sync ตรงๆ → ทั้ง loop หยุด = SSE ของแชททุกคนหยุด

**แก้:**
