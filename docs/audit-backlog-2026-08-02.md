## P1 — anti-pattern เดิมที่ยังไม่ได้ไล่ให้ครบ

### 3. `utils/memory.py` — 3 ฟังก์ชัน query โดยไม่ดู `distances` เลย
`grep` ยืนยัน: `utils/memory.py` มี `.query()` 3 ที่ · อ้างถึง `distances` **0 ที่**

| ฟังก์ชัน | ใช้ที่ไหน | ผล |
|---|---|---|
| `search_memory()` | `routers/chat.py` (regenerate) | คืน top-N เสมอไม่ว่าเกี่ยวหรือไม่ |
| `get_lessons()` | ฉีดเข้า stable block ทุก prompt | เหมือนกัน |
| `get_preferences()` | ฉีดเข้า stable block ทุก prompt | เหมือนกัน |

- เป็นบั๊กตระกูลเดียวกับ `search_vault()` ที่แก้ไปแล้ววันนี้
- ⚠️ **แต่ห้ามใส่ threshold มั่ว** — วัดแล้ว (2026-08-02) คะแนนของ `lessons`/
  `long_term_memory` **ซ้อนทับกันจนตั้งเกณฑ์ไม่ได้** ต้องมี ground truth ก่อน
  (ดูข้อ 8)
- `memory/store.py` มี `.query()` 5 ที่ ใช้ `distances` 3 ที่ — เหลือ 2 ที่ต้องดู

### 4. `search_entries()` (episodic recall) กรอง confidence แต่ไม่กรองความเกี่ยวข้อง
- คำนวณ `score` แล้วเอาไปใช้จัดอันดับ (50/50 กับ confidence) แต่**ไม่มีพื้นขั้นต่ำ**
  → memory ที่ confidence สูงแต่ไม่เกี่ยวกับคำถามยังถูก surface
- `search_long_term()` ไม่มีตัวกรองเลย

### 14. ล้างของเก่าใน episodic memory (ตัดสินใจก่อนว่าจะล้างแค่ไหน)
- `memory_kwan` 92 · `memory_logic` 62 — 62%/76% เป็นข้อมูลสดที่เน่าแล้ว
- **ต่างจาก lessons/skills ตรงที่ห้ามล้างยกคลัง** — episodic ควรเป็นบันทึกบทสนทนา
- เสนอ: ล้างเฉพาะที่ (ก) เนื้อหาเป็นข้อมูลสดที่หมดอายุแล้ว (ข) เป็นข้อความ error
  โดยคง Q&A ปกติไว้ · ใช้ `should_remember()` ตัวเดียวกับ gate ใหม่คัดได้เลย

## บทเรียนที่ควรจำจาก audit รอบนี้

1. **บั๊กเดียวกันมักซ่อนอยู่หลายเส้น** — Thai embedding โดน 3 รอบ · "query โดยไม่ดู
   distances" เจอใน 4 โมดูล · แก้เส้นเดียวแล้วคิดว่าจบคือกับดัก
2. **"ตั้งใจยกเว้นไว้ก่อน" = ที่ซ่อนบั๊กชั้นดี** — `utils/documents.py` ถูกยกเว้นตอน
   แก้รอบ ก.ค. แล้วมีบั๊กเดียวกันเป๊ะ รอดมา 3 สัปดาห์
3. **ของในคลังเป็นขยะ แก้ด้วย threshold ไม่ได้** — พอล้าง lessons คะแนนกลับมาปกติเอง
   (คำถามไม่เกี่ยว 0.452 → 0.184) โดยไม่ต้องตั้งเกณฑ์เลย
4. **prompt ที่ให้ตัวอย่างผิด สอนโมเดลผิดทั้งระบบ** — few-shot example เดียวทำให้ได้
   skill ขยะ 60 อันใน 3 เดือน
5. **เทสที่ไม่ได้พิสูจน์ red ก่อน อาจผ่านแบบหลอก** — เจอเอง 2 ครั้ง (ใส่ `client=None`
   แล้วฟังก์ชัน return ตั้งแต่ต้น ไม่เคยเดินถึงโค้ดที่จะเทส)
6. **อ่านโค้ดอย่างเดียวไม่พอ ต้องยิงจริง** — `preferences` มีบั๊กชั้นที่ 5 (collection
   ถูกสร้างด้วย ef ผิด) ที่มองไม่เห็นจากโค้ดเลย เห็นตอน verify บน prod เท่านั้น
7. **อย่า log ว่าสำเร็จโดยไม่เช็คค่าที่ฟังก์ชันคืนมา** — ตกหลุมนี้เองระหว่าง session
   (log \บันทึกแล้ว\ ทั้งที่ `save_preference()` คืน False ทุกครั้ง)
