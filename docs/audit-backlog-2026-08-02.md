## 17. ต้นตอร่วมของข้อ 16 + false negative ของข้อ 12 — **embedding dilution** (วินิจฉัยแล้ว 2026-08-02)

เบาะแสจากข้อ 12 ("คำถามแมตช์บทเรียนของตัวเองเป๊ะแต่ได้ 0.49") ไล่จนเจอต้นตอ
**ไม่ใช่ปัญหาของ threshold และไม่ใช่บั๊ก Thai embedding** — โมเดลปกติ (`cos(t,t)`=1.0)

**ชั้นที่ 1 — embedding คือค่าเฉลี่ยของทั้งข้อความ** (คำถาม `"หาข้อมูลการสร้างหน้า ui แชทบอท"`):

| ข้อความที่เอาไป embed | คะแนน |
|---|---:|
| หัวข้อบทเรียนอย่างเดียว | **0.913** |
| + เนื้อ 40 ตัวอักษร | 0.658 |
| + เนื้อ 80 ตัวอักษร | 0.524 |
| doc เต็ม (ที่ระบบใช้จริง) | **0.490** |

อิ่มตัวที่ ~160 ตัวอักษร · เราเก็บ "คำถาม+คำตอบ" เป็นก้อนเดียวแล้วค้นด้วยคำถาม
→ คำตอบที่ยาวกว่ากลบสัญญาณของคำถาม

**ชั้นที่ 2 — ตัวระบุ (รุ่น/รหัส) เป็นสัญญาณรบกวน** (คำถาม `"เราเตอร์ที่บ้านยี่ห้ออะไร"`):

| ข้อความ | คะแนน |
|---|---:|
| `"เราเตอร์ที่บ้านคือยี่ห้อเอซุส"` | **0.789** |
| `"เราเตอร์ที่บ้านคือ"` | 0.606 |
| `"เราเตอร์ที่บ้านคือ ASUS RT-BE92U"` (ของจริงใน user_facts) | **0.447** |
| `"ASUS RT-BE92U"` ล้วนๆ | 0.287 |

สองประโยคที่ต่างกันแค่ชื่อรุ่นได้คะแนนกันเอง **0.496** = โมเดลแทบไม่เข้ารหัสตัวระบุ
**ประชด: ตัวระบุรุ่นคือสิ่งเดียวที่เราอยากจำ แต่เป็นส่วนที่ embedding เก็บได้แย่ที่สุด**
→ อธิบายข้อ 16 ครบ (ทำให้ fact สะอาดขึ้น = recall แย่ลง) และอธิบาย false negative ของข้อ 12

### ทางแก้ที่ทดสอบแล้วกับ ground truth 50 คู่

| กลยุทธ์ | ที่เกณฑ์ 0.60 | หมายเหตุ |
|---|---|---|
| doc เต็ม (ปัจจุบัน) | P=0.94 R=0.89 | |
| กุญแจอย่างเดียว | P=0.75 R=0.83 | ❌ **แย่ลง** |
| **max(กุญแจ, doc เต็ม)** | **P=0.86 R=1.00** | ✅ ได้ false negative คืนครบ |

- **"index แค่กุญแจ" ตกทันที** — 3 คู่แย่ลง (−0.11 ถึง −0.39) เป็นเคสที่คำถามใหม่ไม่ตรงกับ
  คำถามเดิมแต่ตรงกับ**เนื้อคำตอบ** · ค่าเฉลี่ยดีขึ้น +0.183 แต่จำนวนที่ผ่านเกณฑ์**ลดลง**
  (16/18 → 15/18) — **ค่าเฉลี่ยหลอก ต้องนับรายตัว**
- ⚠️ **max ได้ F1=1.00 ที่ 0.625 แต่เชื่อไม่ได้** — ช่องว่างระหว่างกลุ่มกว้างแค่ **0.013**
  (0.634 vs 0.621) = overfit บน 50 คู่ · เชื่อได้แค่ **แนวโน้ม** (recall 1.00 โดย precision ไม่ตก)

### ยังไม่ลงมือ — ต้องตัดสินใจก่อน
เป็นการเปลี่ยนวิธี index (เก็บ 2 vector ต่อ 1 memory) กระทบทั้ง `remember()`/`teach()`/
`save_lesson()` + ต้อง re-index ของเก่า · ทางเลือกเสริม: ตัวระบุ (รุ่น/IP/เลขที่) อาจต้องใช้
keyword/substring match คู่ไปด้วย เพราะ semantic search จับไม่ได้โดยธรรมชาติ

📖 บทเรียนเต็ม (ใช้ซ้ำข้ามโปรเจกต์ได้): vault `wiki/concepts/embedding-dilution.md`

- **แก้:** capability gate (`build_registry()` + `_sandbox_available()`) — ไม่ลบโค้ด
  เครื่องที่มี Docker ยังใช้ได้ · `execute_tool` แยก "ใช้ไม่ได้ในสภาพแวดล้อมนี้" ออกจาก
  "ไม่รู้จัก tool" · verified prod: โฆษณา **21 จาก 22**
- ⚠️ **ตั้งใจไม่ mount `docker.sock`** — agent ที่จะรับคำสั่งจากแชทได้ (แผน OpenClaw)
  ไม่ควรมี docker socket ของ NAS · "รันโค้ดไม่ได้" เป็นฟีเจอร์ ไม่ใช่บั๊ก ในบริบทนี้

### 🔴 `fs_list` / `fs_read` / `fs_write` / `fs_search` — no-op เงียบทั้ง 4 ตัว
`_DEFAULT_ROOT = ~/Desktop/ui/sandbox` (layout เครื่อง Mac) → ในคอนเทนเนอร์กลายเป็น
`/root/Desktop/ui/sandbox` ที่**ไม่ได้ mount** → agent อ่านของจริงไม่ได้เลย
และที่เขียนหายทุกครั้งที่ recreate · **ไม่ error แค่คืน "0 entries" ตลอด**
- แก้: mount `${NAS_DATA_PATH}/sandbox:/app/sandbox` + `FS_TOOLS_ROOTS=/app/sandbox`
- verified prod: เขียนไฟล์แล้วเห็นจาก host จริง = persist แล้ว
- **บทเรียน:** เทสหน่วยของ `fs_tools` ผ่านหมดมาตลอด เพราะมันเทส*ตรรกะ* ไม่ใช่*ที่อยู่จริง
  บน prod* — บั๊กอยู่ที่ค่า default ที่คำนวณจากสภาพแวดล้อมที่ผิด ไม่ใช่ที่โค้ด

## 23. ✅ cache หายทุกครั้งที่ recreate — **แก้พร้อมข้อ 6**
