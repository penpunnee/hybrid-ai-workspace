### ~~15.~~ ✅ `user_facts` ไม่เคยถูกสร้างเลย 2 เดือน — **แก้แล้ว** (เจอระหว่างทำข้อ 14)
- **หลักฐาน:** `user_facts` ไม่อยู่ใน `list_collections()` ของ prod เลย ทั้งที่ tier 2.5
  ทำตั้งแต่ 2026-06-03 · รัน `detect_correction()` กับ prompt จริงบน prod 154 ข้อ → **0 hit**
- **ต้นเหตุ:** `teach()` ถูกเรียกทุกเทิร์นจริง (`routers/chat.py:152,575`) แต่ pattern
  บังคับภาษาทางการที่พี่ปอยไม่เคยพูด — และ `r"ผิด[นน]ะ"` **เขียนผิดในตัวเอง**
  (`[นน]` = character class ของ น ตัวเดียวซ้ำเปล่าๆ) จับได้แค่ "ผิดนะ" เป๊ะๆ
  ภาษาจริงคือ "ผิดแล้ว X ต่างหาก" / "ไม่ใช่มั้ง" / "ไม่ใช่ละ"
- **ผลที่ตามมา:** ทุกครั้งที่พี่ปอยแก้ข้อมูลให้ ระบบ *ทิ้ง* เทิร์นนั้น
  (`learn_gate` เห็นเป็น `negative_feedback`) แล้ว **ไม่เก็บของที่แก้ให้เลย**
  → รู้พอที่จะทิ้ง แต่ไม่รู้พอที่จะเรียน · ของผิดเดิมค้างในคลังตลอดไป
- **แก้:** เขียน `_CORRECTION_PATTERNS` ใหม่โดยผูก "ไม่ใช่"/"ผิด" กับคำลงท้าย
  (กัน "ไม่ใช่เรื่องด่วนนะ แต่…") + เพิ่ม "ต่างหาก" + ถอด "จริงๆ แล้ว" (false positive สูง)
  · verified: 154 prompt จริง → จับครบ 3 การแก้ไขจริง **false positive 0**
- ⚠️ **ห้ามรวม `_CORRECTION_PATTERNS` กับ `learn_gate._REJECTION_KW` เป็นชุดเดียว**
  ต้นทุนการเดาผิดคนละทิศ: learn_gate ผิด = ไม่เก็บ lesson (เสียโอกาส) ·
  teach ผิด = เขียนขยะลง `user_facts` ที่ถูกฉีดเข้า context **ทุก prompt** (เสียหายจริง)
- 🔜 **ยังไม่ verify บน prod** — ต้อง deploy ก่อน แล้วดูว่า collection ถูกสร้างจริง
  ด้วย ef ที่ถูก (768 มิติ paraphrase-multilingual ไม่ใช่ MiniLM 384)

### ~~3.~~ ⏸️ `utils/memory.py` — query โดยไม่ดู `distances` — **ยังไม่แก้ โดยตั้งใจ**
วัดใหม่หลังล้างคลัง (ข้อ 14) แล้ว — สมมติฐานที่ว่า "ล้างคลังแล้วคะแนนจะกลับมาปกติเอง

7. **อย่า log ว่าสำเร็จโดยไม่เช็คค่าที่ฟังก์ชันคืนมา** — ตกหลุมนี้เองระหว่าง session
   (log "บันทึกแล้ว" ทั้งที่ `save_preference()` คืน False ทุกครั้ง)

8. **`_embedding_function` ที่อ่านจาก client เป็นของหลอก** — chromadb 1.x เก็บ ef ไว้ใน
   collection config แล้วประกอบใหม่ตอน query · `type(col._embedding_function).__name__`
   คืน `DefaultEmbeddingFunction` (384 มิติ) ทั้งที่ query จริงใช้ ollama 768 มิติ
   → เกือบสรุปผิดว่าวัดด้วยโมเดลผิดตัว **วิธีตรวจจริง: ยิง `query_embeddings` มิติที่สงสัย
   ตรงๆ ดูว่า server ปฏิเสธไหม** + อ่าน `col.configuration_json`
9. **local `.env` ไม่มี `EMBEDDING_MODEL` แต่ต่อ ChromaDB ตัวเดียวกับ prod** — สคริปต์ที่รัน
   จาก Mac ถ้าเรียก `get_or_create_collection()` จะสร้าง collection ใหม่ด้วย MiniLM 384
   แล้ว**ฝังถาวร** (แก้ทีหลังต้องลบสร้างใหม่แบบ `preferences`) · รอบนี้รอดเพราะสคริปต์ใช้
   `get_collection()` อย่างเดียว — ควรตั้ง `EMBEDDING_MODEL=paraphrase-multilingual`
   ใน local `.env` ให้ตรง NAS
10. **สมมติฐานของตัวเองต้องถูกวัดเหมือนกัน** — เข้าเซสชันด้วยความเชื่อว่า "ล้างคลังแล้ว
    threshold จะไม่จำเป็น" (อิงบทเรียนข้อ 3) วัดแล้วไม่จริง · และตัวเลขที่วัดได้เองก็ยัง

    จากข้อมูลที่รู้ว่าอ่อน**
